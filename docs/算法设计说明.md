# 捧月2026 决赛 GUI Agent —— 算法设计说明

## 一、任务背景

决赛阶段，Agent 运行在 Windows 电脑上，通过 ADB **实时操作安卓手机**，根据用户中文指令与手机实时截图，逐步输出操作动作，自动完成真实 App 任务（如京东/淘宝/拼多多筛选下单、美团找店点餐、高德/百度地图路线与导航、喜马拉雅有声书播放与倍速拖动、腾讯视频切清晰度收藏、QQ音乐建歌单播放、跨 App 协作如豆瓣榜单→QQ音乐、美团→高德等）。评委通过观看执行过程人工打分。

## 二、与初赛的关键差异及应对

| 维度 | 初赛 | 决赛 | 本方案应对 |
|---|---|---|---|
| 输入 | 静态数据集截图 | 手机实时 ADB 截图 | 模型驱动、按实际界面决策 |
| 动作 | 5 种 | **11 种** | 解析器/Prompt 全量覆盖 |
| 历史 | 框架回传 `history_actions` | **框架不回传**（仅 instruction/current_image/step_count） | **Agent 内部自维护动作历史 + 带键置顶记忆**，`reset()` 清空 |
| 验证 | ref.json 自动判分 | 评委人工看过程 | 动作稳健、可读、少冗余步骤 |
| 首屏 | —— | 框架只 `press_home()`，首屏是桌面 | Prompt 置顶 OPEN 启动纪律 + 处理上个任务遗留界面 |

> **重要决策**：初赛 `agent.py` 含大量针对具体用例的硬编码坐标/分支，且**强依赖 `history_actions`**。决赛框架不回传该字段且任务完全不同，硬编码会失效甚至帮倒忙。因此**不搬运硬编码逻辑**，只复用「通用动作解析 + Prompt 组装」的工程思想，重写为干净、通用、模型驱动的实现。所有任务相关知识以**通用软策略 / 按需软提示**（讲交互规律、不含坐标/写死步骤、可被模型按实际界面微调）形式提供。

## 三、整体架构与数据流

```
run_tests.py
  └─ DeviceController.connect()           # 切换到 ADB Keyboard 输入法
  └─ TestRunner.run_task()
       agent.reset() → press_home() → screenshot(桌面)
       └─ Agent.act(AgentInput)
            ① 截图平均哈希 + 卡死检测（仅在“画面冻结+原地重复”等明确死局时强制 BACK/SCROLL 脱困）
            ② generate_messages()         # system: 指令+置顶记忆+(按需)App专属提示+11动作+操作策略+最近20步历史(+反思提示); user: 当前截图
            ③ self._call_api(temperature=0, max_tokens=1500)  # 基类统一配置，禁止自建客户端；3 次重试线性退避
            ④ _capture_memory()           # 抽取模型 REMEMBER 标记（支持带键覆盖）→ 置顶记忆
            ⑤ decode_action()             # 从严到松解析 11 动作，兜底 COMPLETE
            ⑥ COMPLETE 误判保活           # 兜底 COMPLETE 但无完成意图 → 降级 WAIT
            ⑦ _apply_guards()             # 轻量护栏（滑动幅度钳制、动作循环打破、OPEN 规范化/重复治理）
            ⑧ clamp + _ensure_valid()     # 坐标钳制 + 标准格式兜底（保证过 _validate_action）
            ⑨ _record()                   # 写入内部历史（含精简 Thought 备注）
       device.execute()                    # 真机操作
```

## 四、核心设计

### 4.1 自维护历史 + 带键置顶记忆（核心适配点）
框架每步只传当前截图、不回传历史，因此 Agent 内部自管两类上下文：

- **动作历史** `List[{step, action, parameters, note}]`：每步成功后追加，`generate_messages` 渲染**最近 20 步**（`HISTORY_WINDOW=20`，TYPE 文本截断）为 `## Previous Actions` 注入 Prompt，提供上下文与防重复依据；每条附带该步精简 Thought 作为“观察备注”。只存文本摘要、不存历史截图，**控制 token**。

- **带键置顶记忆**（`REMEMBER` 机制，本版重点升级）：用有序字典 `store_key → (展示键, 值)` 存储，支持两种写法：
  - **固定事实**（不变，如榜单前五、地点名）→ `REMEMBER: 值`，按内容去重、写一次长期保留；
  - **过程信息**（随步骤变化，如计划/进度/已加已拒清单）→ `REMEMBER【键】: 值`，**同键覆盖**最新值，避免旧快照堆积、自相矛盾或把固定事实挤掉。
  - 容量上限 `16 条 × 500 字符`（足够容纳“5 首歌名+歌手”等长清单），超限按插入顺序淘汰最旧。渲染为 `## Key Info To Remember (pinned)`，**永久钉在 Prompt 顶部**、不随历史窗口滚走。后续步骤只依赖该置顶信息，杜绝凭空臆造或重复回源取数。

- **持久化规划**：对“≥4 子目标/长任务”，Prompt 引导模型在首步用 `REMEMBER【计划】: 1.… 2.…` 钉住有序计划，并用 `REMEMBER【进度】:`（同键覆盖）随完成情况刷新，跨几十步不丢线、不重做已完成子目标。

- `reset()` 在每个用例开始清空历史、记忆与所有卡死状态，杜绝跨用例污染。

### 4.2 11 种动作的稳健解析（`utils/finals_decoder.py`）
- 「从严到松」多级解析：剥离 `<think>` 思考块 → 取**最后一条** `Action:`（模型自我纠正后的最终决策）→ 函数式 `name(args)` → 初赛冒号式 `CLICK:[[x,y]]` → 宽松兜底提取坐标 → 仍失败兜底 `COMPLETE`。
- 坐标支持 `<point>x y</point>`、`[x,y]`、`x,y`、`x y` 多种写法；`double_click` 先于 `click` 匹配（避免子串误判）；`long_press` 解析 `duration`、`wait` 解析 `seconds`、`scroll(point,direction)` 按方向折算起止点。
- `<enter>`/`回车`/字面 `\n` 等统一归一为换行符 `\n`，供无搜索按钮的 App（如得到）回车提交。
- `clamp_action_payload` 统一把坐标钳制到 `[0,1000]`。

### 4.3 通用 Prompt 与策略（`utils/finals_prompt.py`）
完整动作空间 + 坐标系说明 + 「复杂任务先拆有序子目标并持久化计划/进度」引导 + **一条置顶 OPEN 启动纪律（编号 0）+ 23 条编号操作策略**，全部为通用软技能、零任务硬编码。关键内容：
- **OPEN 启动纪律（最显眼）**：启动任何 App 一律 `open(app_name='中文全名')`，**绝不在桌面滑动/进文件夹找图标**——open() 按包名直接拉起，图标在文件夹里也能开。
- **遗留界面处理**：用例间只回桌面不杀进程，OPEN 可能恢复到上个任务的内层页——仅在刚打开那一刻、若是无关遗留页才 `back()` 一次回入口；正在用/有用的内层页不退；卡住或进错页则该退（一次性恢复，不反复 back）。
- 未指定 App 时选已装同类；App 打不开则换应用；加载用 WAIT（网络慢可继续等，由画面是否变化判断是否真卡）。
- 开屏广告找“跳过/×”或等其自动消失，**绝不点广告内容**。
- **搜索流程**：搜索框灰色文字是占位提示（框其实是空的），以“框里是否正好是我的关键词”为准；先点框聚焦→输入自己的短关键词→确认→点「搜索」按钮或匹配联想项；不把占位词当已输入提交、不反复清空空框。
- 路线/地图（起点→终点→途经点对号入座、等定位、认准条目）；榜单走官方入口非搜索；订单/支付停在收银页不真支付；**核对任务给定参数**；按正确指标排序后再比选。
- 滑块/进度条（drag）：起点落在**滑块当前位置**、沿轨道拖到目标，**拖完回看指示是否真移动**再继续。
- **属性无可选项时先看图确认**：任务要某属性（颜色/规格）但页面无选择器时，**先看商品图/文字视觉确认确实匹配**才算满足，绝不盲目确认。
- **无货换品**：商品/规格显示无货/缺货/售罄/该地区不支持销售、或加购按钮置灰 → **不假完成，返回换下一个可购买且符合条件的商品**，真正“已加入购物车”才 complete。
- 多项加入同一新歌单（搜→···→加到歌单→新建一次→其余加入同一歌单，加完若要求则打开歌单播放）；订酒店选房型逐行匹配；**不追 VIP/看广告得时长**；**逐项查属性收集 N 个**（属性进详情页看、按序逐项、`REMEMBER` 记录已加/已拒、心形已是已加态勿再点）。
- **收到“可能卡住”提示时的自救**：先重看截图，目标无效就换元素/换路径或 back，仅在确实还在加载时再等一次。
- `complete` 前逐“具体要素”在屏幕找证据，且 `complete(content)` 写短/留空（避免长串占输出预算被截）。

### 4.4 轻量通用护栏（`agent.py`，无任务硬编码）
- **过早 COMPLETE 拦截**：未做实质操作即完成 → 改为探索性滚动。
- **动作循环检测**：连续 3 次完全相同动作+参数 → 升级式打破（**绝不强制 COMPLETE**）：点击/滚动循环 → 探索滚动 + 反思提示；**WAIT 循环 → 只给温和软提示、不强制 BACK**（网络慢时页面可能仍在加载），真正“画面冻结的死加载”交由 4.5 的 `_dead_loading` 统一处理。
- **OPEN 应用名规范化 + 重复治理**：别名归一（`b站→哔哩哔哩`、`滴滴→滴滴出行` 等）、紧凑/包含匹配；同一应用连续 open 无效 → 回 `HOME` 并提示“改用已装同类应用”。
- **滑动幅度钳制**：单次 SCROLL/DRAG 位移上限 `_MAX_SCROLL_DIST=150`（约 15% 屏），保方向、截位移，防止一次滑太多把目标行/项划走（DRAG 进度条不在此限，避免拖不到位）。
- **COMPLETE 误判保活**：解码在“完全无法解析/仅思考块无 Action”时兜底为 COMPLETE，但若该步文本无任何“完成/complete”意图，则判为解析失败 → **降级 `WAIT` 保活**，避免乱码/纯思考误结束任务。
- **标准格式兜底**：保证输出必过框架 `_validate_action`（CLICK→point、SCROLL/DRAG→起止点、TYPE→text、OPEN→app_name、WAIT→seconds、LONG_PRESS→point+duration），否则安全降级 COMPLETE，绝不抛异常中断用例。
- **空响应保活**：模型多次重试仍空返回（网络/限流/内容过滤）→ 降级一次 `WAIT`，**绝不输出会被判非法的空动作**。

### 4.5 界面停滞反思 + 卡死强制脱困（ReAct 中的 reflection，已精简软化）
对相邻/近邻帧截图做 **32×32 灰度平均哈希（1024 位）** 算汉明距离（阈值 10），细网格能识别“展开下拉/勾选筛选”等小幅变化，避免误判。**设计原则：强制接管只保留“绝对安全”的死局，避免在模型正常重试时打断它**——故仅保留两类**强制 BACK**与两类**强制 SCROLL**：

- **强制 BACK（仅 2 类，安全）**
  - **真卡死**：连续 `≥6` 步“实质操作却画面无变化”**且**最近一直在“重复点同一处”（坐标接近）→ 强制 `BACK`。多选筛选每步点**不同坐标**，门控不满足，**不会误触发**。
  - **死加载兜底**：连续 5 步**纯 WAIT** 且画面完全冻结 → 判加载失败，强制 `BACK`；若页面仍在变化（慢网加载中）则不触发，保护正常等待。
- **强制 SCROLL（打断原地打转，不退出有用页）**
  - 连续 3 次完全相同点击/滚动循环 → 探索滚动；连续 5 步戳同一小块区域（画面因动画在变、画面类护栏失效）→ 探索滚动。
- **单步停滞软提示**：连续 `≥2` 步“实质操作却画面没变”才注入“换目标/先滚动或返回”的软提示（单步无变化属正常重试，不打扰）。

> 设计取舍：早期版本还含“全局无进展横跳强制 BACK”“反复点击同区软提示”等，实测发现它们要么与上述兜底重叠、要么在模型**正常重试**时变成噪声甚至误把筛选/表单状态 BACK 掉，故**移除**，把强制 BACK 收敛到上述两类绝对安全场景，其余交给模型结合截图自行决策（配合 4.3 的“卡住自救”策略）。

> 关键保证：框架对每个用例有 `max_steps` 硬上限，叠加上述脱困机制后，最坏情况只是“耗步数判失败”，**结构上不存在无限挂死**；脱困均带冷却（清帧窗/归零计数），不会连环误触发。纯标准库 + PIL 实现，无新依赖。

### 4.6 按需 App 专属提示（`APP_HINTS`，软参考、不强约束）
针对“确因找不到入口而易失败”的常用 App，维护一张极简提示表，**仅当指令命中该 App 时按需注入一条**（不污染其它任务、不撑 token），且措辞为“通常/以实际界面为准”，模型可微调：
- 命中方式：① 指令**显式出现** App 名优先；② 指令**未指名 App** 时按意图关键词兜底（如“导航/路线/打车”→高德地图），覆盖“找附近 X 并导航”这类不点名 App 的任务。
- 现有条目：**高德地图**（先点“附近”入口→搜类目→筛选“评分最高”同时满足附近+评分；搜索点联想结果行别反复点右上角导致回首页；选店→详情→“到这去”导航）、**百度地图**（不走高速在“智能推荐”下拉里选）、**腾讯视频**（切清晰度/收藏入口）、**今日头条**（长按选“不感兴趣”）。

### 4.7 工程稳健性
- `temperature=0`：输出更确定、稳定（评委复看一致）。
- `max_tokens=1500`：给单次输出足够余量，避免模型把 Thought 写太长时把后面的 Action 行挤掉被截断（这是单次回复的天花板而非目标值，正常一步只用约 150–250 token，不会平白消耗总预算）。
- 模型调用 3 次重试 + 线性退避，缓解限流/瞬时网络抖动；usage 透传用于框架 token 统计。
- 仅日志截断打印原始输出，不打印 Key / 大图 base64。
- **模型/接口配置完全沿用 `agent_base.py` 官方设定**，不读取任何覆盖用环境变量，保证本地与正式评测执行一致；**API Key 仅走 `VLM_API_KEY` 环境变量，绝不硬编码**。

## 六、创新点小结
1. 针对决赛「框架不回传历史」的关键差异，设计 **Agent 内部自维护历史 + 带键覆盖置顶记忆（REMEMBER）** 机制：固定事实长期保留、过程信息同键刷新，并据此**持久化计划/进度**，兼顾上下文质量、跨步信息保真与 token 成本。
2. **从严到松多级动作解析 + 标准格式兜底 + COMPLETE 误判保活**（剥离思考块、多 Action 取最后决策），对模型多样化/异常输出高度鲁棒，保证零非法动作中断、不被乱码误结束。
3. **纯通用、零任务硬编码**的策略体系（OPEN 纪律、搜索占位词、路线对号入座、订房选房型、无货换品、属性看图确认、不追 VIP/广告、逐项收集 N 个、加完播放、遗留界面处理等），把真实 App 交互规律沉淀为可泛化经验。
4. **精简后的卡死脱困**：基于相邻帧平均哈希的轻量 reflection，把强制接管收敛到“画面冻结+原地重复”等**绝对安全**的两类强制 BACK 与两类强制 SCROLL，其余交模型自决，**既杜绝无限挂死又不打断正常重试**（无新依赖）。
5. **按需 App 专属提示**（显式名优先 + 意图关键词兜底，软参考可微调）与 **App 名关键词泛化**（别名表 + 包含匹配），在不污染通用性的前提下补齐“易迷路”入口知识。
